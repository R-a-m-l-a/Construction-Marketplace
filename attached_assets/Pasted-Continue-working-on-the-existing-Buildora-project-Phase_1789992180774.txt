Continue working on the existing Buildora project.

Phase 1 and Phase 2 are complete and working.

Implement **PHASE 3 ONLY: Construction Cost Calculator**.

Do NOT rebuild existing features.

The goal is to add a useful, functional construction cost estimation tool for users in Pakistan.

---

# 1. Main Feature

Create a dedicated:

**Construction Cost Calculator**

accessible from the main navigation and an appropriate homepage section.

The calculator should allow a user to enter basic project information and receive a transparent estimated construction cost.

This is an ESTIMATION tool, not a quotation.

Clearly display:

**"This is an approximate estimate. Actual costs vary by location, material quality, design, labor rates, market prices, and contractor."**

Do not present estimates as guaranteed prices.

---

# 2. User Inputs

Create a clean, easy-to-understand form.

Include:

### Location

Allow the user to select/search a city or area.

Reuse the existing Phase 2 location functionality where practical.

Examples:

* Islamabad
* Rawalpindi
* Peshawar
* Lahore
* Karachi

Do not hard-code the calculation to one city.

---

### Property Size

Allow common Pakistani property-size units:

* Marla
* Kanal
* Square feet
* Square yards

Allow the user to enter a custom size.

Example:

5 Marla

or

1125 sq ft

Do not assume that every "marla" is the same size.

Use a configurable conversion system rather than scattering hard-coded conversions throughout the application.

Clearly indicate the conversion being used.

For the initial Pakistan MVP, use a configurable default for marla rather than pretending there is one universal standard.

---

### Covered Area

Ask for:

**Estimated covered area**

Allow:

* Square feet
* Percentage of plot area

If percentage is selected, calculate the covered area from the plot size.

Example:

Plot = 5 marla
Covered area = 80%

Then calculate the corresponding approximate covered square footage.

Allow the user to override the calculated covered area manually.

---

### Number of Floors

Options:

* Ground floor
* Ground + 1
* Ground + 2
* Custom number

Calculate total covered area appropriately.

Do not simply multiply everything blindly if the user has manually entered total covered area.

Clearly distinguish:

**Plot Area**

from

**Total Covered Area**

---

# 3. Construction Quality

Provide three simple options:

### Basic

Economical materials and finishes.

### Standard

Mid-range materials and finishes.

### Premium

Higher-end materials and finishes.

# 4. Construction Type

Allow the user to choose an appropriate construction type such as:

* Grey Structure
* Complete Construction

If "Complete Construction" is selected, include finishing-related costs.

If "Grey Structure" is selected, exclude or separate finishing costs.

Make this distinction very clear.

---

# 5. Calculation Engine

Create a clean calculation service/module rather than placing all calculations directly inside the UI component.

The calculation should consider:

* Total covered area
* Location
* Construction type
* Quality level
* Number of floors

Return an estimated RANGE rather than a single false-precision number.

Example:

Estimated construction cost:

**PKR 1.8M – 2.2M**

Do not use these example numbers as actual market prices.

The values must come from a clearly separated configurable pricing/estimation data layer.

---

# 6. Pricing / Estimation Data

IMPORTANT:

Do not claim that hard-coded prices are current Pakistani market prices.

For the MVP, create a clearly identifiable configuration/data layer for estimation assumptions.

For example:

* cost per square foot ranges
* grey-structure cost assumptions
* finishing cost assumptions
* quality multipliers
* location multipliers

Keep these values centralized.

Do NOT scatter pricing numbers throughout components.

Structure the code so that later we can replace these assumptions with:

* Admin-managed pricing
* Database pricing
* Verified market data
* City-specific pricing

without rewriting the calculator UI.

# 16. Accuracy and Safety

This calculator is for early planning only.

Clearly communicate that:

* Actual construction costs vary.
* Material prices change.
* Labor rates vary by city and contractor.
* Architectural design affects quantities.
* Structural design affects quantities.
* Soil/foundation requirements can significantly change costs.
* Finishing choices can significantly change costs.

For structural or engineering decisions, recommend consulting a qualified professional.

Do not claim the calculator replaces an architect, engineer, quantity surveyor, or contractor.
